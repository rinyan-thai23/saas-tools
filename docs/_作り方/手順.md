# 業種別の比較サイトの作り方（民泊ツール比較で実際にやった手順）

民泊ツール比較（記事42本）を、リサーチ→執筆→校閲→修正→ビルドの順で作った。別の業種でも、同じ順で作る。
実績の数字と所要は `../民泊ツール比較/制作メモ.md`。

## 全体の流れ（フェーズ）

| フェーズ | やること | 状態（民泊ツール比較） |
|---|---|---|
| 0 | 業種と案件（製品）を決める。Capterra のデータで候補を絞る | 完了（11製品） |
| **1** | **商品ページを1商品ずつ作る**（`商品ページの作り方.md`）。口コミ(関連順・新着順)の取得、公式サイトの確認、Web検索3回、口コミの集計、ページ執筆 | **完了（11本）** |
| 2 | 商品ページを材料に、比較・代替・乗り換え・日本対応・買う直前の記事を書く（読者の悩み別） | 旧版42本あり。商品ページに合わせて作り直す予定 |
| 3 | 校閲（事実の照合）、ビルド、公開前の確認 | 一部実施済み |

### フェーズ1の実績（民泊ツール比較）
- 1商品あたり、時計の実測で約1分（下調べスクリプト使用後。最初の2本は約2分）。サブエージェントは使わず、1本ごとに30秒の間隔。
- 商品ページは、サイトの軸になる。トップから全商品ページへ入れるようにし、比較・代替の記事は商品ページへリンクして短くする。
- 並列エージェントで一気に作ると、読者に響かない報告書調になった。**ゼロイチの作成は1本ずつ**（理由と詳細は `商品ページの作り方.md`）。
- 詳しい計測と学びは、各サイトの `デザイン作業メモ.md` に記録する。

## 前提（ユーザーが決めた条件）

- 狙うのは「買う直前」「乗り換え」「比較」の検索だけ。検索ボリュームは気にしない（1日10アクセスで十分）。
- 20〜50本のミニサイト。読者は、その業種で、ジャンルの製品名を知っている人。
- **リサーチ役・ライター役・校閲役は必ず別のエージェント**にする。事実は「事実カード」に残し、ライターはカードにない事実を書かない。
- 確かめていないことは「未確認」と書く。「記載が見つからなかった」と「できない」を混ぜない。
- 広告（アフィリエイト）リンクは `/go/<製品slug>/` の内部リンクにして、冒頭にPR表記。後で遷移先だけ差し替える。

## 手順

**案件（製品）が決まったら、まず `商品ページの作り方.md` で商品単体の紹介ページを作る。比較・代替・乗り換えはその後。** 下の表の段階3（並列リサーチ）に入る前に、少なくとも中核製品の商品ページを作っておく。

| 段階 | やること | 出力 | 担当 |
|---|---|---|---|
| 1 | 業種を決める。`データ/03_製品マスタ.tsv`、`04_詳細/製品詳細.tsv` で製品を探し、中核8＋補助3を選ぶ。読者像と記事一覧（比較・乗り換え・代替・日本対応・買う直前の5型、30〜40本）を決める | `docs/<業種>比較/README.md`（設計） | 親 |
| 2 | 事実カードの書式を決める（`民泊ツール比較/事実カード/_スキーマ.md` をコピー） | `事実カード/_スキーマ.md` | 親 |
| 3 | リサーチ：製品2つずつ＋制度・国内の話題を、並列で。公式ページを開き、事実・出典URL・取得日・確度（確認済／第三者のみ／未確認）で書く。末尾に「調べられなかったこと」 | `事実カード/*.md` | リサーチ役（並列5〜6人） |
| 4 | 執筆：記事1本4〜7本ずつ配る。材料はカードだけ | `記事/*.md` | ライター役（並列8人） |
| 5 | 校閲：記事を書き換えず、カードと1つずつ照合して指摘を書く | `校閲/<slug>.md` | 校閲役（並列7人） |
| 6 | 共通方針を決める：指摘の多いものを、全記事共通のルールにする | scratchpad か `共通方針.md` | 親 |
| 7 | 修正：校閲レポートと共通方針を渡して、指摘を反映 | 修正済みの `記事/*.md` | ライター役（修正担当） |
| 8 | ビルド：`ビルド/build.py` でHTMLにする。リンク切れ・PR表記・内部メモの残りを機械検査 | `docs/minpaku/` | 親 |
| 9 | 記録：制作メモに工程・作業量・品質を書く | `制作メモ.md` | 親 |

## 運用のコツ

- 5時間制限に当たると、並列のエージェントが一斉に止まる。止まった人は、リセット後に SendMessage で再開できる。起動する人数は制限を見て決める。
- 1人に渡す記事は4〜7本。プロンプトは毎回、書式・見本・禁止事項を全部書く（前の会話は引き継がれない）。
- 校閲は、記事が「ない」と書いた箇所が、カードでは「記載なし」「未確認」になっていないかを重点的に見ると、指摘が出る。
- 記事の長さは指定しても超えやすい（指定1,500〜3,500字に対し、実際は出典を除いて約3,000〜13,000字）。見本が長いと、長く書く。見本は短いものにする。
- 公開前に、人が決めること：運営者名・連絡先、アフィリエイト申込と紹介URL、置き場所とドメイン。
- このリポジトリは公開をしない。ビルドした `docs/minpaku/` は、別の場所へ移して公開する。

## ビルド（そのまま使える）

`民泊ツール比較/ビルド/build.py` と `go-links.tsv` を、新しいサイトのフォルダへコピーする。

- `pip install markdown`
- `python3 ビルド/build.py`（既定は noindex）、`--publish` で公開前の厳しい検査
- 記事の形式：先頭に frontmatter（title, slug, type, products, description, cards, updated, pr）。`type: 固定` はトップ直下のページ。
- 本文の内部リンクは `/articles/<slug>/`、`/go/<製品slug>/`、`/compare-table/` などの形。
