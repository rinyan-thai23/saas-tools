## 1. 何を作ったか

- 海外の民泊管理ツール（PMS・チャネルマネージャー）を、日本で3〜15室運営する人が「申し込む直前」に比べるためのミニサイト。
- 狙いは、買う直前・乗り換え・比較のキーワードだけ。検索ボリュームは気にしない。
- 条件：リサーチ役・ライター役・校閲役を必ず分ける。事実は「事実カード」に残し、ライターはカードにない事実を書かない。確かめていないことは「未確認」と書く。

### 5-2. 修正の結果（修正後）

- 7人の修正役が、要修正・注意の全件と、軽微の大半を反映した。反映しなかった指摘は、Guesty の Capterra の数字（記事は README の値、カードは別の値）の1件だけで、追加調査依頼に回した。
- 内部用語（「事実カード」「カード名」など）は、記事の本文と出典欄から除去した。
- 修正後の再校閲は未実施。したがって「指摘が全部なくなった」とは言えず、「指摘は反映した」までが事実。

### 5-3. 強み

- 事実を「確認済／第三者のみ／未確認」で分け、記事にも出している。公開本文の「未確認」は623回、「確認済」は440回。
- 「記載が見つからなかった」と「できない」を分けている。日本向け機能（円建て、宿泊者名簿、住宅宿泊事業法、スマートロック）の多くは、公式に記載が見つからなかったため、そう書いている。
- 広告表示が一貫している。冒頭にPR表記、`/go/` は PR リンク、Sirvoy・Hostfully にはリンクなし。ビルド時に機械でも検査する。
- リサーチ・執筆・校閲・修正の役が別のエージェントで、作業の記録が残っている。

### 5-4. 弱み

- 長さがばらつく。指定は1,500〜3,500字だったが、実際は出典を除いて約2,900〜13,000字。1回目のライターの記事5本（alt-guesty、jp-yen-invoice、switch-spreadsheet-to-pms、vs-guesty-hostaway、vs-igms-hospitable）は出典を除いて8,000〜10,500字と特に長い。比較表は約13,000字。2回目の記事は3,000〜5,000字に収まった。
- 「未確認」が多い。読者の悩みは「日本で使えるか」だが、その答えの多くが「公式に記載が見つからなかった」で、決め手になりにくい。
- 記事同士の言い回しは、共通方針でそろえたが、完全には揃っていない可能性がある（再校閲していない）。
- 比較する外部の基準がない。他の比較サイトとの読み比べ、検索順位、読者の反応、申込の成約率は、測っていない。

### 5-5. 品質を決めている前提と限界

- 記事の正しさは、事実カードの正しさに依存する。カードは、リサーチ役が公式ページ等を開いて作ったもの。人が出典URLを開き直して確かめてはいない。

### 次に使える運用のコツ

- 1人に渡す記事は4〜7本が目安。1人の作業は、執筆で5〜9分、修正で1〜3分、校閲で3〜5分（制限に当たらなければ）。
