# 第一工程：商品単体の紹介ページを作る（案件が決まったら最初にやる）

**比較・代替・乗り換えの記事は、商品ページができてから書く。** 民泊サイトでは、商品を深く知らないまま比較に着手し、サブエージェントを67体まで同時に動かして、読者に響かない報告書調の記事を42本作った。その反省で、この工程を最初に置く。

## なぜ商品ページが先か（whoから）
- 読者は「その商品が自分に合うか」を知りたい。比較表より先に、**1つの商品を深く知っている先輩の一言**が欲しい。
- 商品ページはサイトの軸になる。後の比較・代替・乗り換えは、商品ページへリンクして書けば短く済む。
- AI（ライター）も、商品ページを材料にすれば、事実を取り違えにくい。

## 手順（1商品ずつ。並列にしない）

| 順 | やること | 道具 |
|---|---|---|
| 1 | Capterra の口コミを取る。**関連順と新着順の両方** | `取得スクリプト/08_口コミ関連順100件.py` に `most_recent` を付けた回と付けない回。統合は `取得の記録.md` の手順 |
| 2 | 公式サイトを自分の目で見る（トップ・機能・料金・会社概要。言語、対象規模、パートナー表記、料金の公開の有無） | curl でHTMLを取り、本文を読む |
| 3 | Webを検索する（**1商品あたり3〜4回**）。キーワードは「商品名」＋ 口コミ／評判／調査／まとめ／日本で | WebSearch（standard） |
| 4 | 口コミを読む。件数の傾向（良い点・改善点で多い話題）、投稿者の規模・使用期間、低評価は全文 | 集計スクリプト＋目視 |
| 5 | ページを書く（下の型） | 親が1人で書く |
| 6 | ビルドして目で確認 | `ビルド/build.py` |

**サブエージェントは使わない。1商品ずつ、親が1人で順番に作る。**（ゼロイチのコンテンツ作成では並列実行しない。並列にすると速さが優先されて品質が落ちる、という実感があるため。）
- 1本できたら **30秒のインターバル** を置いてから、次の商品に進む。
- 下調べは `取得スクリプト/09_商品調査.py`（口コミ集計＋低評価＋公式サイト本文）で、1商品1回で済ませる。
- 型が固まった後で、検証・校閲のような「判断の少ない作業」に限り、並列を検討する。

## ページの型（H2／H3）
1. 先に結論（30秒）：誰に向くか・向かないか・日本の注意点
2. 〇〇とは？（何ができるツールか）
3. 主な機能（H3で機能ごと）
4. 料金（公開か非公開か。分かる範囲）
5. 評判・口コミまとめ：良い口コミ（H3）／悪い口コミ（H3）。投稿者の規模・使用期間も書く
6. 日本で使える？（日本語、民泊新法、国内予約サイト）
7. 向いている人・向かない人
8. 申込前に聞くこと
9. よくある質問（H3＝質問、直下の段落＝答え。構造化データに自動変換される）
10. 関連記事（比較・代替・乗り換え）

## 書き方のルール
- **出典URLは本文に書かない。** Capterra などの口コミは、要約して日本語にする（原文の引用・転載をしない）。
- ただし信頼のため、①「公式サイトで確認」と「海外の口コミから」を文中で区別する ②末尾に確認日を1行 ③確かめていないことは「未確認」。根拠のメモ（URL）は作業メモに残す。
- 口コミの数字は「おおよそ」と書く（キーワード集計は目安）。Capterra の評価点は海外レビューと明記する。
- 日本の運営者の声ではない場合は、そう書く。
- 構造化データ（JSON-LD）：`type: 商品` のページは、ビルドが Article・SoftwareApplication・FAQPage を自動で入れる。**他社が集めた評価点（aggregateRating）は入れない**（自社のレビューではないため）。

## 計測する（初回は必ず記録）
Web検索の回数、所要時間、ツール呼び出し数、概算トークン、できあがりの文字数を、`民泊ツール比較/デザイン作業メモ.md` に書く。

# フェーズ2：比較・代替・乗り換えなどの記事の作り方

商品ページ（フェーズ1）ができてから作る。**1本ごとに、必ず新しくWeb検索で調べる。**

## ルール
1. **1本ずつ、親が1人で作る。** 並列にしない。1本できたら **1分** 空ける。
2. **作る順番**：材料への依存が少ないものを先に、全体の材料が要るものを後に。（比較→代替→乗り換え→買う直前→日本対応→英語版のメリット→固定ページ・トップ）
3. **タイトルにジャンル名**（民泊）を入れる。例：`【民泊】A と B どっちがいい？…を比較`
4. **毎回のWeb検索は2回**（英語の比較・口コミ／日本語の比較）。自社の比較ページは「自社の主張」と明記。
5. **材料は商品ページ**。数字は商品ページにあるものだけ使う。新しい数字は、商品ページにも足す。
6. 書き終えたら `取得スクリプト/10_記事チェック.py` を実行（タイトル、リンク、禁句、金額の照合）。
7. 型：結論 → 早見表 → 料金 → 契約 → 口コミ → 日本の注意 → 状況別おすすめ → 質問リスト → FAQ → 関連記事。
8. 旧版は、同じ slug で上書きして置き換える。

## チェック担当（エージェント）について
今は使わない。理由：数字の照合は機械（スクリプト）の方が正確で、エージェントを増やすと品質が落ちた経験があるため。必要になれば、1体だけ、順番に動かす。
