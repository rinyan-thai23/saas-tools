# 【体験・ツアー】予約システムの乗り換えチェックリスト｜二重予約を防ぐ「つないでから切る」順番

## 先に結論

> - **二重予約を防ぐ一番の原則は、「新しい方をつないでから、古い方を切る」順番です。** 切る順番を間違えると、その間に二重予約が起きます。
> - **ほとんどの場合、切り替えの日までの予約は古いシステムで、その日以降の新しい予約は新しいシステムで受けます。**
> - **2つのシステムを並行して動かす期間は、短く、毎日見比べる**のが一般的です。
> - この記事は、海外の導入・移行の解説（複数の会社のブログ）と、日本の予約・システム移行の解説を元にした**一般的な進め方**です。各社の公式手順ではありません。

## 0. 乗り換える前に決めること

- [ ] **いつ乗り換えるか**：繁忙期の前ではなく、予約が少ない時期に。移行に必要な日数は、海外の解説では「小さな事業者で数日〜1週間ほど」とされています（目安。製品や商品の数で変わります）。
- [ ] **誰が担当するか**：移行の責任者を1人決めます。毎日の見比べも、その人が行います。
- [ ] **今のシステムの解約条件**：契約期間、解約の方法、データを書き出せる期間を、書面で確認します。
- [ ] **新しいシステムの契約条件**：日本の事業者として契約できるか、円で受け取れるか、日本語のサポートがあるか。各製品の商品ページの「日本で使える？」の節に、確認できたこと・できなかったことをまとめています。

## 1. 事前に書き出す（古いシステムが使えるうちに）

- [ ] **顧客の一覧**（名前、連絡先）
- [ ] **先の日付の予約をすべて**（日付、商品、人数、名前、連絡先、支払い済みか、どの販売先から来たか）
- [ ] **過去の予約**（会計や分析のため）
- [ ] **未使用のギフトカード・クーポン**がある場合は、その残高
- [ ] **商品の設定**（定員、開始時間、料金、キャンセルの規定、締め切り）を、画面を見ながら書き出す

**FareHarbor の例**：他社の移行案内によると、FareHarbor は予約レポートを期間を指定してCSVで出せます（[手順](/articles/switch-fareharbor-to-bokun/)）。

## 2. 新しいシステムを準備する

- [ ] 無料トライアルや、テスト用のアカウントで、**実際の商品を1〜2つ**登録します。
- [ ] テスト予約を入れて、**確認メール、決済、キャンセル**が正しく動くか確認します。
- [ ] 予約を取り込む方法を確認します（表計算での取り込みなど）。製品によって違います。
- [ ] **日本語の窓口がある製品**（[rezio](/articles/rezio/)、[Bókun の日本版](/articles/bokun/)）なら、設定の相談を先にします。

## 3. 予約サイト（OTA）を「つないでから切る」

- [ ] **新しいシステムに、予約サイトを先につなぎます。** この時点では、古いシステムも動いています。
- [ ] **両方に在庫が出ている間は、空き枠を絞る（売り止めにする）**など、二重予約が起きない運用にします。
- [ ] 新しい方で、**予約サイトごとの商品の対応づけ**を確認します（予約サイトの分類は、自分の商品の分け方と違うことがあります）。
- [ ] 新しい方の接続が正しく動いたのを確認してから、**古い方の接続を外します。**
- [ ] 接続が「つながっている」と表示されていても、**実際に予約が入るか、テストで確認します。** 口コミに、「つながっていると表示されたが、設定が正しくなく予約を逃した」という声があります（Bókun）。

**日本の予約サイト（じゃらん、アソビュー、楽天など）を使っている場合**：どの製品も、日本のサイトとの連携は確認できていません。連携がないと、日本のサイトの在庫は**手で**合わせることになります。使いたいサイト名で、各社に聞いてください。

## 4. 切り替えの日

- [ ] **切り替えの日付を、全員に伝えます**（スタッフ、電話の担当者）。
- [ ] その日から、**新しい予約は新しいシステムだけ**に入れます。電話・窓口の予約も、新しいシステムに入れます。
- [ ] 切り替え前の予約は、古いシステムで対応を続けるか、新しい方に入れ直すか、決めておきます。
- [ ] **切り替え時点で、最後にもう一度、予約を見比べます。** 切り替えの直前に入った予約が、漏れていないか確認します。
- [ ] **団体や貸切の予約が切り替え日をまたぐ場合**は、両方のシステムで、すべての枠を手で確認します。

## 5. 並行運用の期間（短く、毎日見比べる）

- [ ] **1〜2週間**ほど、新旧の予約を毎日見比べるのが一般的です（日本のホテル向けの移行の解説にもあります）。体験・ツアーでは、商品と予約の数に合わせて短くしても構いません。
- [ ] ずれを見つけたら、原因を書きます（電話の予約の入れ忘れ、接続の遅れなど）。
- [ ] 見比べは、**1人の担当者**が行います。

## 6. 古いシステムを止める

- [ ] すべての予約サイトの接続が、新しいシステムに切り替わったことを確認します。
- [ ] 古いシステムにしかない予約（切り替え前の予約）が、**すべて実施された**ことを確認します。実施前に解約しない。
- [ ] **データの書き出しを、解約の前に、もう一度**行います。
- [ ] 解約の連絡と、請求が止まることを、書面で確認します。

## 7. 失敗したときの戻し方

- [ ] **古いシステムに戻す手順を、先に決めておきます**（日本の移行の解説でも勧められています）。
- [ ] 戻す条件（例：2日続けて二重予約が出た）を決めておきます。
- [ ] 古いシステムの解約は、新しい方が安定してからにします。

## 乗り換えで多い失敗

- **電話・窓口の予約を新しいシステムに入れ忘れる**
- **先の日付の予約を取り込み忘れる**
- **古い方を先に切って、予約サイトの在庫が空になる／古いまま残る**
- **サポートが英語で、設定の相談ができない**

## よくある質問

### 並行運用は何日ですか？
一般的には1〜2週間です（日本のホテル向けの解説）。体験・ツアーでは、商品と予約の数で変わります。公式の決まりではありません。

### 切り替えは、いつがいいですか？
予約が少ない時期です。繁忙期の直前は避けます。

### 日本の予約サイトを使っていても、乗り換えられますか？
乗り換えられますが、日本のサイトとの連携がない製品では、在庫を手で合わせる必要があります。連携できるか、各社に聞いてください。
